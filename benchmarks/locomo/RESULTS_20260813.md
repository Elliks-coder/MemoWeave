# Hy-Memory Ultra × LoCoMo 25 题评测结果

## 结论

Hy-Memory Ultra 能稳定完成长期会话写入，并有较好的事实检索与拒答能力；主要短板是
相对时间归一化、开放域推理，以及“已召回证据 → 得出正确答案”的转化能力。

本次不是完整 LoCoMo 官方排行榜成绩，而是固定的 25 题分层子集。原始模型裁判分为
15/25（60%）；人工审计发现题号 32 的裁判理由与候选答案矛盾，纠正后为 16/25
（64%）。两项都保留，避免只报告更好看的数字。

## 数据与协议

- 来源：LoCoMo（ACL 2024）官方 `locomo10.json`，sample `conv-26`。
- 数据文件 SHA-256：`79FA87E90F04081343B8C8DEBECB80A9A6842B76A7AA537DC9FDF651EA698FF4`。
- 规模：19 sessions、419 turns、时间跨度 2023-05-08 至 2023-10-22。
- 题目：multi-hop、temporal、open-domain、single-hop、adversarial 各 5 题。
- 写入对象：Caroline 映射为 Hy-Memory `user`；非对抗题统一询问 Caroline。
- 检索：每题 Top 10；回答模型仅接收检索结果，不读取原始全文。
- 判分：同一 LLM 根据官方参考答案做 JSON 判分，并对失败样本人工复核。
- Hit@K：Hy-Memory 搜索结果没有暴露 session id，使用记忆日期是否命中人工证据
  session 日期计算，因此是近似的 session-level evidence recall。

类别 5 原题 184 被排除：它把“Caroline 会什么乐器”标为不可回答，但完整对话中
Caroline 明确说会弹木吉他，真值冲突。最终改用题号 185。

## 失败分析

### 1. 时间事实被召回，但日期没有正确归一化

Temporal 的 Hit@1 为 100%，答案准确率却只有 40%。例如：

- “昨天参加支持小组”被存成事实，`memory_at` 是会话日期 5 月 8 日；回答器直接输出
  5 月 8 日，而正确事件日期是 5 月 7 日。
- “上周五参加领养会议”和“上周二加入活动组织”保留了相对时间措辞；回答器把会话
  日期当成事件日期或选择拒答。

这说明瓶颈不在向量召回，而在抽取阶段没有把相对时间解析成独立的事件时间字段。

### 2. 开放域推理过度保守

Open-domain Hit@5 为 80%，准确率只有 20%。对于政治倾向、宗教程度、是否会回国等
需要综合推断的问题，回答提示的“只用记忆、不要猜测”让模型频繁回答不知道。这提升了
对抗拒答（100%），但损害了合理推断，体现出 abstention 与 inference 的权衡。

### 3. Evidence recall 高于端到端准确率

Hit@10 已达到 90%，可回答题准确率仍只有 50%。即使证据日期已进入 Top 10，列表不完整、
时间信息丢失和回答策略也会导致最终错误。因此不能只用 Recall@K 宣称记忆系统效果好。

### 4. 图关系写入存在假成功

System 2 生成了 4 次 `add_edge`，参数使用 `schema_1`、`schema_2` 等临时占位符，而创建
节点后的真实 ID 是 UUID。Kuzu 的 `MATCH` 未命中任何节点时没有抛异常，调用层仍报告
`success: true`。只读核验发现 `RELATED_TO` 实际为 0 条。

这属于明确的实现缺陷：工具层应该解析本轮新建节点 ID，并在创建边后检查受影响行数。

### 5. Cross-domain sweeper 有运行时警告

日志出现 `_scan_collisions fetch failed: list indices must be integers or slices, not str`。
本轮 9 个 basic schema 的行为 embedding 已生成，但 collision/core 合并为 0，不能据此
声称跨域核心人格归纳已经验证成功。
