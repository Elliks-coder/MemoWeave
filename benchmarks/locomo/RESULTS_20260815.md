# Hy-Memory Ultra × LoCoMo 修复后 25 题回归

## 结论

本轮修复后回归为 **19/25（76%）**，较修复前的 16/25（64%）提高 12 个百分点。
19 个会话全部写入成功，Temporal 从 2/5 提升到 5/5，Kuzu 的临时引用解析、真实写入核验
与失败传播均通过端到端核验。当前版本可以进入更大规模评测，但仍应重点观察开放域零召回、
多跳证据覆盖和“召回正确但回答选错证据”三类问题。

这不是完整 LoCoMo 官方成绩，而是从同一条长对话中按五个官方题型各取 5 题组成的固定
25 题回归集，适合用于开发回归，不适合直接与完整榜单成绩横向比较。

## 数据与协议

- 数据：LoCoMo `locomo10.json` 的 `conv-26`。
- 规模：19 sessions、419 turns，时间跨度 2023-05-08 至 2023-10-22。
- 题型：Multi-hop、Temporal、Open-domain、Single-hop、Adversarial，各 5 题。
- 检索：normal / profile / proactive 阈值均为 0.4；normal Top 10；L7 默认参与召回。
- 写入阶段候选召回：独立阈值 0.3，后接 LLM reconcile，不改变用户查询阈值。
- 回答：只读取检索到的记忆，不读取原始完整对话。
- 判分：模型仅根据参考答案和候选答案裁决，不带之前会话上下文。
- 证据指标：L2/L7 保留原始 turn ID 后计算精确 Recall@K；对抗题没有正证据，不计召回。

## 剩余错误与通用优化方向

### 1. 开放域零召回

“政治倾向”和“宗教程度”两题在 0.4 阈值下所有桶均为 0 条结果。相关原始事实存在，但问题
与事实之间是“价值观 → 可能倾向”“信仰符号 → 宗教程度”的语义桥接，单次向量检索不稳定。

建议增加**零结果时的保守二阶段回退**：只在所有桶都为空时，以更低阈值取少量候选，并要求
回答器明确标注为推断；同时以 Adversarial 拒答率作为护栏。该策略按检索状态触发，不按题目
关键词触发，不会针对具体 case 过拟合。

### 2. 召回正确但回答选错证据

“画展作品灵感”正确事实位于 normal 第 3 名（Recall@5=1），回答却混合了相邻的诗歌朗读、
自我接纳等艺术记忆。建议在回答前增加轻量的全桶重排或 evidence selection，重点计算问题中的
事件、实体、因果触发词与候选事实的逐项一致性；具体事件题应避免把多条相似主题记忆拼成答案。

### 3. Multi-hop 完整证据覆盖不足

Multi-hop 的 Recall@5/10 只有 30%/40%，说明 Top K 常被同一主题的近重复事实占满。建议用
MMR、按 session/turn 去重或子主题覆盖约束提高多样性，再让回答器聚合，避免简单扩大 K。

### 4. 参考答案不完整与时间语义歧义

部分错误答案包含完整对话中真实发生、但参考答案未列出的事件或符号；“暑假计划”还存在
早期计划与后续计划并存的问题。系统性评测应同时保留原始裁判分，并对这类样本标注
`reference_incomplete` / `temporal_scope_ambiguous`，不要把基准缺口反向写成业务规则。

### 5. 生命周期告警

评测退出时的 MetricsCollector 两个 pending task 已修复：后台任务现在会保存引用，在 cache
关闭前取消并等待任务结束，同时执行最后一次 flush。相关回归测试已加入。
